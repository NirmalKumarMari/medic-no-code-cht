# Database/storage work plan — November 4 revision

Authority: revised FINAL Solution Design §§8–9, 14. This replaces the earlier KB/vector/Memory work plan.

| Owner | Current scope |
|---|---|
| Yash / workflow data | Four DynamoDB tables, typed repositories, exact snapshot binding, human decisions, audit, callback recovery, release history, deterministic rejected-rule index |
| Storage owner | One private versioned SSE-KMS S3 artifact bucket, immutable artifact helpers, screened whole-source upload, full guideline/curated-primer prompt-context receipts |
| App/agent/workflow owners | Model prompt/cache integration, actual source/primer selection, citations and logic checks, Cognito/UI, Step Functions, compiler/harness, deployment and CHT test environment |

No Knowledge Base, vectors, embeddings, sync jobs, semantic history agent or AgentCore Memory. Public sources and real clinician-reviewed examples remain required. Model inputs contain full source context; no agent-facing retrieval tool exists. Intake remains a bounded structured call; Drafting and Change Planner receive the appropriate context from trusted code.

DynamoDB uses PK `changeId`, SK `sk`. Changes holds `META`, `SNAPSHOT#`, `BUILD#`, `TEST#`, `DEPLOY#`, `CONTEXT#` records and internal target pointers. Approvals holds immutable `CONTENT#`/`DEPLOY#` decisions, `IDEMP#` receipts, and materialized rejection partitions `HISTORY#tenant#pathway#fingerprint`. Audit is append-only timestamp/ID chronology. Tokens stores private task tokens and recoverable outbox delivery. Required decisions/audit have no TTL. No fifth database or table is introduced.

Sources/artifacts use ArtifactRef `{ bucket, key, versionId, sha256, contentType }`. Snapshot hash still binds baseline, specification, exact evidence versions, context receipts, golden cases and compiler/toolchain identity. The legacy `retrievalEvidenceRefs` field now points to complete direct prompt-context receipts. Changing meaningful/hash inputs requires a new snapshot/review; an identical-input infrastructure retry preserves its approval.

Exact-rule flags are produced deterministically during Logic Checks and refreshed before content review. Rejection history is tenant/pathway scoped, strongly consistent, and committed in the same transaction as the content rejection. Matches are advisory and preserve the prior decision reference; they do not prove clinical invalidity and do not auto-block approval. No approval/audit records are generated by agents.

Implementation checks: artifact-storage source/context tests and root IaC tests; workflow package local DynamoDB consistency, history, separation, stale-version, callback and release tests. Actual AWS source-screening/model/runtime/auth/CHT integration remains an explicit acceptance step. Document exact resource outputs and cloud inventory. Do not seed demo data as part of this migration.

Next integration order: finalize actual guideline/pathway and curated primer → provision authorized source storage/roles → connect screened full context and audit callback → freeze snapshot refs → run deterministic checks/history → human approvals/build/test → deploy/verify in isolated CHT. Prove citations and test results from actual inputs rather than from prewritten successful outcomes.

See `docs/STORAGE.md`, `docs/HANDOFF.md`, and `packages/workflow-data/docs/INTEGRATION.md` for contracts and retention. No destructive cleanup or schema migration may erase old evidence.
